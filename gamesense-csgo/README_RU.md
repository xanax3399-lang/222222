# Skeet v3: точки верхней части головы / CS:GO

Пункт **2** сохраняет поведение v2: точки NL и расчёт тормозного импульса.
Пункт **3** включает v3: до трёх точек у верхней границы капсулы головы из
выбранной записи анимации. Точки проходят прежние проверки трёх матриц,
урона и hitchance GS. Это собственная геометрическая добавка, не полный перенос
сканера NL и не подтверждённое исправление всех случаев приседания.

В `skeet_nl_points.ini`: `[v3] head_crown=1`, `head_crown_percent=95` (50..99).
В режиме 2 эти параметры не действуют. Пункт 5 сохраняет отдельные счётчики v3.
Полностью перезапустите игру после изменения INI. Старые гипотезы анимации —
пункт 6. Новый инжектор и DLL используют протокол 4: берите согласованную пару.

V2 сохранена на коммите `72aa34f0956c619ba5f24c9e5c19c6dabf7fd7ff`, отдельной
веткой и тегом. Её исходный архив не меняется: [версии и хеши](versions/README_RU.md).
10 фиксированных случаев переходника v2 сравниваются с новым режимом 2.

Новые точки ограничены капсулой выбранной записи, в том числе при изменении её
высоты в тестах. Текущий duck amount игрока не подмешивается в историческую
геометрию. Контролируемый тест высоты укрытия проверяет лишь геометрию;
реальная видимость, урон, попадания и производительность на карте требуют
проверки в CS:GO. Интерполяция/экстраполяция и выбор записи GS не менялись.
Полные autostop/quick stop NL ещё не перенесены; статус ниже относится к v2-базе.

Основа — пользовательский `Skeet_NL_Hypotheses_8802.rar`. Исходные файлы
оболочки импортированы отдельно; их хеши находятся в `archive_baseline.json`.
Исторические утверждения и инструкции архива сохранены в `ARCHIVE_README_RU.md`.
Они не являются результатами новой проверки.

**NL-геометрия подключена к пути сканирования GS через `0x4335E9D0`.**
Собираются `skeet.dll` и соответствующий `injector.exe`. В инжекторе выберите
**2 — NL points** (также Enter), либо `injector.exe --mode nl-points`.
Сначала выполняется штатный генератор GS. Его точки сохраняются, допустимые
точки NL добавляются к ним. Центр, используемый последующими проверками GS,
остаётся центром исходных точек GS. Пустой результат NL не удаляет результат GS.
Выбор цели/записи/точки, расчёт урона и hitchance выполняет GS. Полный
алгоритм выбора точки NL не перенесён. Код и данные CS2 не использованы.

**Расчёт тормозного импульса NL подключён к общей остановке GS** в режимах 2/4.
В `skeet_nl_points.ini`: `[movement] nl_brake=1` (по умолчанию); `0` возвращает
прежнее торможение GS, сохраняя точки NL. После изменения полностью перезапустите
CS:GO. Пункт 5 показывает `GS brake samples`, `NL brake applied` и скорость/
импульс последнего применения. Счётчик учитывает достижение переходника после
родного расчёта трения, а не все запросы остановки или выстрела.

GS сохраняет решение о начале остановки, трение, эффективные параметры
оружия/ходьбы/приседания и условия выстрела. Перенесён численный блок NL;
**полный контроллер autostop/quick stop NL не перенесён**. Более ранний выстрел
в игре ещё не подтверждён. Контракт и ограничения —
[recovery/stop-analysis](recovery/stop-analysis/README_RU.md).

Масштаб задаётся в `skeet_nl_points.ini`: `head_scale_percent=80`,
`body_scale_percent=80`, диапазон 0..100. `reduced_head=1` оставляет пять точек
головы вместо семи. Настройки применяются при загрузке DLL. Автоматический
масштаб NL по состоянию оружия восстановлен отдельно, но в игру пока не подключён.
Пункт 1 оставляет штатный GS; 6 включает прежние гипотезы анимации; 4 объединяет
гипотезы с точками; 5 показывает счётчики. Для проверки новых точек достаточно 2.
Пункт 5 сохраняет `module_diagnostics.log` рядом с `injector.exe` и ждёт Enter
в интерактивной консоли. `--diagnostics` также сохраняет файл, без ожидания.
Папка `reports` содержит проверки сборки; это не счётчики вашей игровой сессии.

Предыдущая сборка заменяла исходный список точками NL и могла оставить его
пустым после фильтрации. Кроме того, менялся средний центр списка. Обе ситуации
исправлены без снижения минимального урона или hitchance. Отказ выстрела при
минимальном уроне 100 на карте ещё требует проверки пользователем после обновления.

Восстановлено по x86-ядру NL для CS:GO с SHA-256
`682ce73b371349f87da6fd9365f8550e240dcdb97951e80445e70286275ad96e`:

| Часть | Результат и граница проверки |
|---|---|
| Геометрия головы, `0x414AC630` | Центр + четыре основные точки; в полном режиме ещё две диагональные. Сравнение с нативными инструкциями генератора и его пересечения капсулы. Масштаб задан одинаковым явным входом. |
| Геометрия тела, `0x41490FA0` | Центр + две боковые; для hitbox 6 дополнительная верхняя точка. В тесте отсутствующая функция `client.dll` заменена внутренним пересечением капсулы NL. Эквивалентность именно игровой функции не установлена. |
| Масштаб, `0x4149ED20` | Ручной процент, автоматическое сжатие по расстоянию и разбросу, ограничение масштаба. В эмуляторе выполняется родная CRT-функция синуса. Возвращаемый результат отдельного оружейного helper в fallback-ветке задаётся входом теста. |
| Пересечение капсулы в новом C++ | Собственная аналитическая реализация; не буквальная декомпиляция SSE-кода. Проверяется сравнением выходных координат. |
| Полное управление генератором | Маска хитбоксов, чтение конфигурации и состояния оружия, выделение памяти и метаданные нативных точек не перенесены. Входы модуля явные. |

Проверены 1000 наборов геометрии, 1000 наборов масштаба и 37 некорректных
входов геометрии. Подробности и ограничения — `reports/points_validation.json`.
Недопустимые/вырожденные входы возвращают `false`, оставляя выходной объект
неизменным. Такой результат должен оставлять управление штатному генератору.

## Подключение и память

Найденный генератор GS `0x433FD9B7` работает с тремя вариантами матриц
анимации; его два прямых вызова — `0x433341CA` и `0x4335E9D0`.
Его временный буфер инициализируется функцией `0x433D5A95`:
`begin = this + 0x10`, `end = begin`, `capacity = begin + 0x48`.
При размере точки `0x18` это **три точки**. NL использует записи размером
`0x50` и может выдавать семь точек. Записать туда результат NL напрямую
означает выйти за границы буфера и потерять смысл метаданных.

Переходник меняет только вызов `0x4335E9D0`, возвращается в `0x4335E9D5`
и сохраняет ABI, группу хитбокса, вес и флаги точки. Координаты передаются
через собственное хранилище на десять записей (до трёх исходных + семь NL).
Дополнительный переход в `0x4335EA97` восстанавливает исходный центр в XMM6/7/5
до его использования родным кодом. Переход сохраняет GPR, флаги и полный x87/SSE
контекст; изменяются только три низкие float-полосы с координатами центра.
Итоговый буфер этого вызывающего
участка расширяется со 112 до 256 записей: родная функция добавления GS не
проверяет вместимость. Старые записи копируются до переключения указателей.
Хранилище разделено по потокам/волокнам и адресам вложенных списков, освобождается
FLS callback при завершении потока/волокна. Освобождение временного списка GS
`0x433CCE8E` не освобождает данные: это `RET 0`.

Каждая новая точка проверяется **родной функцией пересечения GS `0x43418772`**
для трёх вариантов матриц. Точки, не прошедшие проверку, отбрасываются.
Если контекст, геометрия или хранилище не поддержаны либо все новые точки
отклонены, сохраняется исходный результат GS. Другой вызов `0x433341CA` и специальная ветка поз остаются GS:
для их дальнейшего формата данных переходник не подтверждён.

Переход устанавливается до контрольной суммы и подготовки VM. В эмуляторе
исполняются скомпилированный production-переходник, родная функция пересечения,
родной цикл обработки списка и функция добавления GS (включая 200 записей).
Проверены стек, регистры, соседняя память, изоляция хранилищ, ошибки выделения
и сохранение штатных кандидатов, включая случай нулевого результата NL.
Для головы используются контролируемые результаты исходного генератора,
для одного случая тела выполняется сам исходный генератор GS с заменой CRT memcpy.
Это не проверка стрельбы в игре. Отчёт: `reports/points_bridge_validation.json`.

## Воспроизведение проверки математики

На Linux с Python 3 и g++:

```sh
python -m venv .venv
.venv/bin/pip install unicorn==2.1.4
mkdir -p build reports
g++ -std=c++17 -O2 -shared -fPIC -ffp-contract=off -fno-fast-math \
    -Wall -Wextra -Werror tests/points_probe.cpp -o build/points_probe.so
.venv/bin/python tests/validate_points.py --donor /path/to/nl.bin
g++ -std=c++17 -O2 -ffp-contract=off tests/points_smoke.cpp -o build/points_smoke
./build/points_smoke
python tests/validate_points_contract.py
```

Донор сверяется по SHA-256 до выполнения любых инструкций. Семь изменений
нормализации из исходной оболочки перечислены с исходными байтами в
`recovery/nl_geometry_patches.json`. Изменения применяются только к копии
образа в эмуляторе. DLL инициализация, инъекция и игра не запускаются.

Полная сборка: установить `requirements-build.txt`, запустить
`python build_windows.py`, затем `python tests/validate_points_bridge.py` и
`python tests/verify_points_release.py`. GitHub Actions дополнительно загружает
полученную DLL через Windows `LoadLibrary` и проверяет экспортируемые статусы.
Запуск инжектора в игру и проверка попаданий на карте CS:GO не выполнялись.
