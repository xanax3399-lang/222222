# GS + NL API bridge 0.1.0 — CS:GO Legacy 8802

Это частичная совместимость с публичным Neverlose **CS:GO** Lua API. В этой
версии не реализован полный API NL и не перенесены его резольвер, prediction,
сканер или контроллер DT. API с похожими названиями из других проектов и CS2
не использовались. Публичные определения типов описывают интерфейс, а не
реализацию Neverlose. Алгоритмы адаптера написаны отдельно; их эквивалентность
бинарнику NL не проверена.

## Как подключить

1. Полностью закройте CS:GO и распакуйте новую пару DLL + инжектор в новую папку.
2. Запустите CS:GO через этот инжектор, выбрав нужный режим. Пункт 3 — v3.
   Сам мост доступен во всех режимах; он не переключает режим и не меняет DT.
3. Скопируйте содержимое `lua/` в используемую Gamesense папку Lua-скриптов,
   где загрузчик находит локальные модули. `gsnl.lua` должен находиться в пути
   поиска `require`. Загрузите `gsnl_example.lua` обычным способом в меню Lua GS.
4. Нужен штатный доступ GS к `ffi` (разрешение unsafe scripts в вашей сборке).
   Мост не снимает это ограничение. Без доступа к FFI загрузчик выдаст ошибку.

```lua
local api = require('gsnl')
local v = api.vector(3, 4, 0)
client.log(v:length()) -- 5; вычисление длины выполняет C++ в DLL
client.log(api.capability('rage_exploit:force_charge').status) -- unavailable
local s = api.native.snapshot() -- только диагностические счётчики нашей DLL
```

`gsnl.lua` — небольшой загрузчик, не вся реализация. Через штатный
`client.find_signature` он находит в уже загруженной `skeet.dll` уникальную
таблицу `GSNL_API_V1_TAB!`, проверяет ABI/размер и указатели, получает Lua-код из DLL и создаёт
адаптер в текущем Lua-состоянии. Он не загружает второе ядро, не инжектит DLL
и не вызывает Lua из фонового потока. Для векторов/углов используются нативные
C++ функции. События, меню, сущности и отрисовка переводятся во встроенном Lua
через действующий API GS. Это **не** полностью нативная реализация API NL.
Ревизия загрузчика 2: нет зависимости от `ffi.load` или разрешения внешних
функций через `ffi.C`. В исходном GS эти возможности ограничены: это подтверждено
разбором его LIBINIT и функции разрешения C-символов. Общие ограничения FFI GS
не изменяются. Предыдущий загрузчик ревизии 1 с этим рантаймом несовместим.

## Обычный API GS и окружение NL

Глобальные `ui`, `entity`, `globals`, `renderer` GS сохраняются. Они также
доступны через `api.gs`. Для NL-подобного кода есть отдельное окружение:

```lua
local api = require('gsnl')
local run, err = api.load([[
    local group = ui.create('My script')
    local enabled = group:switch('Enabled', true)
    events.render:set(function()
        if enabled:get() then
            render.text(nil, vector(24, 100), color(255), '', 'Hello')
        end
    end)
]], '@my-nl-script')
assert(run, err)
run()
```

Окружение `api.load` служит для разделения имён; это не песочница безопасности.
Код имеет те же разрешения, что и основной скрипт GS. Модули сторонних авторов
`neverlose/*`, их зависимости, магазин и аккаунт NL не включены.

## Проверка совместимости

В архиве находятся `GSNL_API.md` и `gsnl_api_manifest.json`: полный перечень
символов **зафиксированного справочника**, а не заявление о полном покрытии NL.
Каждый символ имеет статус `supported`, `partial` или `unavailable`.
`api.supports(name)` возвращает true только для supported. Для partial прочитайте
`api.capability(name).notes`: реализация существует с ограничениями.
Неизвестные/недоступные функции и неподдерживаемые параметры дают ошибку.

Основные ограничения:

- `render.text` и `measure_text`: `font=nil`, стандартный шрифт и флаги GS.
  Произвольные NL-шрифты, blur, rotation/clip stacks не реализованы.
- `ui.create(group)` размещает контролы в GS `LUA/B`. Вкладки и пути меню NL
  не совпадают с GS. Для ссылок используйте явное сопоставление:
  `api.map_menu({'Aimbot', 'Example'}, ui.reference('RAGE', 'Aimbot', 'Enabled'))`.
  После этого соответствующий `api.ui.find` возвращает обёртки над ссылками GS.
  `MenuItem:override` не эмулируется записью постоянной настройки.
- `events.createmove` использует GS `setup_command`. Доступны `view_angles`
  (pitch/yaw), `forwardmove`, `sidemove`, `upmove`, `move_yaw`, кнопки `in_*`
  в виде boolean, чтение `command_number`, `tickcount`, `choked_commands`.
  Запись разрешена только углам, движению и кнопкам. `send_packet`, `no_choke`,
  `force_defensive`, `block_movement`, roll и остальные неизвестные поля дают
  ошибку. Если callback завершился ошибкой, его изменения команды не применяются.
  В `createmove_run` доступны только чтение номера команды и choke.
- `events.aim_fire` переводит HC и координаты, но не предоставляет NL shot angle.
  `aim_ack` не подменяется событиями GS с другим содержимым.
- Сущности поддерживают базовые методы и чтение скалярных/векторных netprops
  через GS. Array netprops и прямые записи через объект NL не реализованы.
- DT force_charge/force_teleport, анимационные состояния, матрицы и NetChannel
  не реализованы. Мост не фабрикует значения, не включает unsafe recharge и
  не добавляет новые хуки стрельбы/движения.
- `api.native.snapshot()` читает отдельные диагностические поля. Это не
  синхронный снимок тика; счётчики не показывают точность и причины промахов.
- `common.get_unixtime` использует GS `client.unix_time`. Календарные
  `get_date/get_system_time` требуют явно доступного `os.date`; при его отсутствии
  выдают ошибку. Сам загрузчик не требует наличия стандартной библиотеки `os`.
- `api.dispose()` снимает зарегистрированные через мост события и прекращает
  вызов UI-колбэков. При обычной выгрузке Lua он вызывается автоматически.

## Нативный ABI

Версия `0x00010000`. C++-заголовок в архиве: `api/gsnl_native.h` (в репозитории
`source/api_bridge/native.h`). При использовании только объявлений определите
`GSNL_API_DECL_ONLY`; реализация находится в DLL. Экспорты:
`gsnl_abi_version`, `gsnl_source`, `gsnl_snapshot`, `gsnl_length3`, `gsnl_dot3`,
`gsnl_normalize_yaw`, `gsnl_api_table`. Таблица содержит 16-байтный маркер,
версию, размер и шесть указателей; в x86 её размер 48 байт. Она расположена
в читаемом исполняемом разделе, чтобы её находил и сканер только code sections.
Таблица проходит обычные ASLR-релокации загрузчика; после загрузки не изменяется.
Строка кода живёт до выгрузки DLL; её нельзя изменять.
Для snapshot передайте точный размер `GsnlSnapshot` (72 байта). Счётчики
32-битные, могут переполниться; это диагностические данные.

## Проверки

CI выполняет встроенный код и настоящий загрузчик в LuaJIT с контролируемым API
GS, проверяет ошибки/отписку/неизменность глобальных таблиц и нативную математику.
Windows отдельно загружает настоящую DLL и проверяет её экспорты и встроенный
код. Игровая совместимость с настоящей Lua-системой CS:GO пока не проверена.
