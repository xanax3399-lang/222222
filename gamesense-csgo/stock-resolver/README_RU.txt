Native C++ resolver / GameSense / CS:GO Legacy 8802 / Windows x86

Установка
1. Выгрузите прежний stock_resolver.lua в меню GS и отключите его автозагрузку.
2. Полностью закройте CS:GO. Распакуйте НОВЫЙ архив целиком в отдельную папку.
3. Запустите injector.exe. Пункт 2 / Enter — GS + нативный C++ резольвер.
   Пункт 1 — штатный GS. После смены режима требуется перезапуск игры.
4. Инжектор сообщит: Native C++ resolver connected to FrameStageNotify.

Отдельный Lua-файл, ffi.load, unsafe scripts и ручная загрузка драйвера
для этой версии не требуются. Расчёт, сбор данных и применение решения
реализованы в C++ внутри skeet.dll. Инжектор больше не копирует Lua и не
останавливается из-за отсутствующего stock_resolver.lua (Windows error 2).
CS2 не поддерживается. DLL и инжектор должны быть из одного архива.

Как подключено
DLL получает VClient018, ожидает установку штатного обработчика кадров GS
и подключает свою обёртку к FrameStageNotify. Перед GS на NET_UPDATE_END
собирается свежая история; затем обязательно вызывается прежний обработчик.
Смещения свойств ищутся по RecvTable DT_CSPlayer и его базовым таблицам,
а не записаны заранее для конкретной карты. Интерфейсы и размер структур
рассчитаны на x86 CS:GO Legacy 8802.
Читаются simtime, eye yaw, LBY, pose, скорость, duck, позиция, флаги, команда,
состояние жизни, Steam/user ID, время, задержка и cvar интерполяции.
Результат записывается в проверенные поля GS Force body yaw / value.
Смещения этих полей сверены с настоящим x86 кодом GS plist.get / plist.set.
Неподдерживаемая таблица/интерфейс/раскладка дают явный отказ установки.

Оценка и ограничения
Это самостоятельно написанная эвристика -60/0/+60 с опорой на историю LBY,
направление движения и устойчивое чередование yaw. Это не полный NL resolver.
При недостатке подтверждений и в воздухе используются решения штатного GS.
В памяти: до 64 игроков x 16 записей; повторы simtime не дублируются.
Смена игрока, смерть, dormancy, откат simtime и телепорт сбрасывают историю.
Ручной Force body yaw и позднейшие ручные изменения имеют приоритет.
Отключение/потеря цели восстанавливают только собственные действующие overrides.
Файлы в цикле обновления не записываются, сканирования сигнатур на каждом кадре нет.
Оценка evidence НЕ означает процент попадания. Нативная версия не обучается
по unknown/miss и не сопоставляет player_hurt с поколением lag record.
Полные анимационные слои/матрицы костей не реконструируются; удалённые usercmd
сервер не раскрывает. Штатные backtrack, урон/hitchance, DT и autostop остаются.
Старые патчи NL points/braking и v3 crown/fire/recharge в этой сборке выключены.

Настройки skeet_nl_points.ini (применяются при запуске DLL)
[resolver]
enabled=1       ; 0/1, при 0 работает штатный GS
confidence=65   ; 50..95, порог согласованности наблюдений, не вероятность попадания
fps_limit=0     ; 0 выключен; необязательный лимит 30..500 для игры
Плавность уровня другого чита и улучшение попаданий этими настройками не гарантируются.
Лимит восстанавливает исходный fps_max при выходе в меню; ручные изменения сохраняются.

Проверка подключения
Инжектор -> пункт 5 сохраняет module_diagnostics.log рядом с injector.exe.
Секция Native C++ resolver: state 3, installed 1 — обработчик подключён.
Во время игры растут Frame callbacks / network updates / records.
Active overrides — число игроков, к которым сейчас применено решение.
Manual blocks — ручные настройки; GS fallbacks — недостаточно данных модели.
Эти счётчики не измеряют точность. loader_last.log сохраняет стадии запуска.

Автотесты: модель C++, сохранение чужих полей GS, настоящий x86 код plist,
Windows LoadLibrary реальной DLL, штатные выключатели старых патчей, CLI,
полный C++-драйвер с контролируемыми Source-интерфейсами, RecvTable, вызов
прежнего обработчика кадров и цепочка snapshot -> модель -> GS override.
Source-интерфейсы в тесте — фикстура; реальный матч в CS:GO не запускался.
Точность, FPS и конкретная установка игровых хуков требуют проверки на карте.
