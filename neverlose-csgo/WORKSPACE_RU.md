# Рабочая база Neverlose CS:GO

Текущие изменения DLL/инжектора и интерфейса: [BUILD_STATUS_RU.md](BUILD_STATUS_RU.md). Ниже сохранён исходный обзор восстановления; утверждение об отсутствии изменений исходников относится к состоянию до работы над интерфейсом.

Собрана из C++-проекта `neverlose-master-1` из первого RAR и настоящего `neverlose/bins/nl.bin` из `nublain.rar`. Исходные C++ файлы сохранены без изменений. Вместо указателя Git LFS установлен бинарник, совпадающий с его SHA-256: `682ce73b371349f87da6fd9365f8550e240dcdb97951e80445e70286275ad96e`. Используются только материалы CS:GO.

**Это исходники оболочки и патчей с бинарным ядром. Полного восстановленного C++ ядра здесь пока нет.** Наличие файлов `.cpp` не означает, что все алгоритмы клиента представлены в них.

## Что восстановлено из ядра

- Проект Ghidra: `recovery/projects/NeverloseCSGO.gpr`. Процессор `x86:LE:32:default`, соглашение Windows, база сырого образа `0x412A0000`.
- Разобраны 10 начальных функций по адресам из исходников оболочки: проверки/поиск записей, генераторы точек, анимация и два текстовых элемента меню. Файлы `recovery/decompiled/*.pseudo.c` и ассемблер рядом — **непроверенный псевдокод**, не оригинальный и не готовый к сборке C++.
- Для отдельной аналитической копии применены 2469 записей из существующих таблиц NOP/исправления переходов оболочки. Файлы: `recovery/images/`, журнал каждого изменения `normalization.json`, экспорт `decompiled_normalized/`. Эта копия не заменяет `neverlose/bins/nl.bin` и не предназначена для запуска. Полная инициализация импорта, игровых интерфейсов и динамических адресов в ней не выполнялась.
- В нескольких функциях остаются непрямые переходы, неразрешённые обращения и предупреждения декомпилятора. Завершение декомпиляции не доказывает полноту функции или правильность типов. Автоматический экспорт нельзя включать в клиент как замену ядра.
- Функция по адресу `0x413F6D50` отдельно перенесена в собираемый C++20: `recovery/reconstructed/record_expiry.hpp`. Названия полей сохраняют адреса/смещения, поскольку их полная семантика не доказана. Возвращаемый результат совпал с исходными x86-инструкциями в эмуляторе Unicorn на 4066 наборах, включая граничные значения и переполнение. Это проверка одной функции, не всего Ragebot. В клиент она не подключена.

## Проверки

Проверка исходников нашла все 94 ссылки на файлы C++/заголовков/ресурсов из проектов Visual Studio. Все исходные файлы, кроме намеренно заменённого LFS-указателя, совпадают с архивом по SHA-256. Это проверка наличия файлов, а не сборка Windows.

В Linux прошли существующие `rage_record_logic_test` и `crouch_hitscan_logic_test`, а также 4066 сравнений восстановленной функции с оригинальным машинным кодом. Результаты: `recovery/workspace_validation.json` и `record_expiry_validation.json`.

Повторение проверок из любого каталога:

```sh
python3 -m venv /workspace/neverlose-csgo/recovery/.venv
/workspace/neverlose-csgo/recovery/.venv/bin/python -m pip install -r /workspace/neverlose-csgo/recovery/requirements.txt
bash /workspace/neverlose-csgo/recovery/run_checks.sh
```

Потребуются Python 3, g++ с C++20, Unicorn 2.1.4. Сборка Windows и запуск в CS:GO здесь не выполнены. Основной Windows-процесс сборки и требуемые версии MSVC/Rust описаны в исходном `README.md`.

## Меню в стиле CS2 внутри CS:GO

Такое оформление можно реализовать для CS:GO, однако `fix_menu_extra.cpp` изменяет отдельные участки существующего меню через адресные патчи. Это не исходник полного интерфейса. SDK описывает только открытие, прозрачность и состояние редактора стиля.

Практический путь — собственный C++ интерфейс с отдельными отрисовкой и вводом и адаптером к реальным настройкам CS:GO-клиента. Чтобы все переключатели управляли Ragebot, нужно отдельно установить форматы и привязки настроек, сохранение конфигов и поведение при загрузке/выгрузке. Подтверждённых привязок ко всем настройкам пока нет. Внешнее сходство с CS2 само по себе не требует переноса кода CS2.

Дальнейшее восстановление ядра требует ручного уточнения структур, соглашений вызова, непрямых переходов и поведения каждой заменяемой функции. Только после такой проверки отдельный участок можно безопасно перевести из бинарного ядра в изменяемый C++ модуль.
