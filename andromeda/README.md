# Andromeda: восстановление предоставленного кода

Это восстановленный код из `andromeda.txt`, а не оригинальный авторский проект.
Сохранены все 564 определения функций, доступные в предоставленном файле.
Основной код приложения присутствует; это не отдельный загрузчик.

## Файлы

- `andromeda_source.lua` — единый файл с упрощёнными телами функций,
  компилирующийся в LuaJIT. В основной функции сохранены 35 частей,
  необходимые для ограничения длины переходов LuaJIT.
- `andromeda_flat_source.lua` — вариант для изучения, где основная функция
  собрана в одно тело без диспетчера частей. Компилируется в Lua 5.4;
  LuaJIT отклоняет его с ошибкой длины управляющей структуры.
  Для GameSense используйте `andromeda_source.lua`.
- `functions/` — отдельные фрагменты всех 564 функций. Они требуют общих
  переменных основного файла и не являются самостоятельными скриптами.
  `f096_flat.lua` содержит дополнительный цельный вариант основной функции.
- `function_index.json` — номера функций, строки в обоих исходниках,
  описатели захвата переменных и размеры исходных кадров.
- `constant_strings.json` — 2170 различных строковых значений из метаданных.
  UTF-8 представлен текстом, остальные байты — шестнадцатеричной записью.
  Это извлечение литералов, а не заявление о расшифровке всех строк приложения.
- `prototype_metadata_reference.lua` — исходные массивы метаданных,
  которые больше не нужны упрощённой программе, но оставлены для сверки.
- `reference/andromeda_supplied.lua` — точная копия присланного файла.
- `manifest.json`, `validation.json` — контрольные суммы, состав и проверки.
- Python-скрипты и `requirements-recovery.txt` — воспроизводимое восстановление.

## Что изменено

Убраны неиспользуемые массивы операндов и лишние вложенные `do`-блоки.
Константные служебные выражения упрощены внутри блоков, удалены только
ненужные присваивания без побочных эффектов с учётом переходов управления.
Часть служебных циклов копирования развёрнута. Для 230 функций с непередаваемым
кадром статические обращения к регистрам заменены локальными `slot_N`.
Сохранены общие изменяемые кадры и ячейки захвата там, где они нужны замыканиям.
Исходные строковые литералы сохранены без переписывания байтовых экранирований.
Общая реализация проверок запуска вынесена в `new_tick` с сохранением точек
проверки и исходных ограничений. Часть явных переходов `goto` остаётся.

Это не восстановление исходных авторских имён и комментариев. Они отсутствуют
в предоставленном материале. Названия `slot_N`, `fN`, служебные кадры и описатели
захвата — оставшаяся промежуточная форма, сохранённая ради точности поведения.

## Ограничения исходного материала

Файл уже был изменён до этой работы: f1 и f2 содержат адаптированный запуск и
диагностику; f47, f109, f116, f418 — диагностические замены аварийных процедур;
f108, f115, f416 пустые; f403 уже заменена реализацией XOR. Их доступное поведение
сохранено. Эти тела нельзя выдавать за подтверждённый оригинал автора.
Также сохранены 34 присутствовавшие во входе проверки повреждённых инструкций.

Внешние модули GameSense отсутствуют в предоставленном файле. Видимые ссылки:
`gamesense/base64`, `gamesense/clipboard`, `gamesense/csgo_weapons`,
`gamesense/entity`, `gamesense/inspect`, `gamesense/msgpack`, `gamesense/pui`.
Это перечень обнаруженных строковых ссылок, а не полный проверенный список
требований исполнения. Нужны игровые API, LuaJIT/FFI и подходящая версия клиента.

## Проверки

Приложение в GameSense не запускалось. На отдельном ограниченном Lua runtime
созданы все 564 фабрики функций без запуска приложения и доступа к native FFI,
файловым операциям или сети.

На пяти синтетических сценариях для каждой функции получено 477 совпавших
завершённых результатов: 471 сравнение значений и 6 сравнений только структуры
возвращённых функций. Это затронуло 189 идентификаторов. Остальные 2331 сценарий
завершились ошибками в обеих версиях и не считаются проверкой поведения.
12 сценариев оказались недетерминированными уже при повторе исходной функции
и также не засчитывались как успешные сравнения. Различий в сравнимых результатах
не найдено. Различия текстов ошибок из-за имён переменных и расположения кода
записаны отдельно; равные ошибки не доказывают эквивалентность.

Дополнительно проверены 30 векторов быстрого XOR, 30 векторов исходных
арифметических тел XOR, 14 сравнений SHA-256 с входной реализацией и 6 стандартных
HMAC-векторов на входной/выходной версиях. Унаследован дефект SHA-256 для сообщения
`a`, повторённого 55 раз: hex- и binary-результаты отличаются от стандарта в обеих
версиях. 24 из 28 стандартных SHA-проверок прошли; четыре отказа соответствуют
этому случаю в двух представлениях и двух версиях. Дефект не исправлялся, чтобы
не менять поведение предоставленного приложения при восстановлении.

Проверки не подтверждают работу меню, игровых обработчиков, всех замыканий,
протоколов сервера или всех путей исполнения. Авторский исходник и исходная
обфусцированная VM для независимой сверки отсутствуют.

## Повторение

Из каталога распакованного архива, Python 3.12:

```sh
python3 -m pip install -r requirements-recovery.txt
python3 recover.py
python3 build_compatible.py
python3 slim_metadata.py
python3 validate.py
python3 catalog.py
```

Эти команды заново создают выходные файлы в текущем каталоге восстановления.
Сохраните собственные изменения перед повторением. `validate.py` проверяет
соответствие предоставленному коду; унаследованные от него ошибки стандарта
SHA-256 явно отражены в JSON-отчёте.
